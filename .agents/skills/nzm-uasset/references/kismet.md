# Kismet 使用规范

## 获取可读字节码

先按[本地参考库规范](../../../../docs/workflows/kismet-evidence.md)查找 `kismet/` 中与目标资产同来源的完整 JSON，使用 `rg --files --no-ignore kismet` 包含被忽略文件。检查目标函数是否有 `ScriptBytecode`；只有 `ChildProperties` 等参数声明属于函数签名，不是函数实现。

`ScriptBytecode` 缺失或为空时，检查导出方式、函数标志和诊断，区分“没有蓝图脚本”“此次未读取”“解析失败”。单凭空字段不能认定函数是 Native 或没有行为。

当前项目有两个可复用入口，从项目根目录运行：

导出器默认使用项目内 `MD/_local/nzm-assets/tools/FModel.Cli.dll` 和 `MD/_local/nzm-assets/nzm.json`。显式传入的相对路径同样以项目根目录为基准；默认值由通用导出器维护，赛季入口直接复用。

`nzm-assets/tools/FModel.Cli.exe` 是资源导出用的自包含单文件程序，不提供这套 DLL 反射入口。内置 EXE 存在不代表 Kismet 所需 DLL 已安装；不能把 EXE 改名或直接作为 `-AssemblyPath`。只有已有兼容 DLL 安装时才使用下面的旧入口。

```powershell
# Assets 是 nzm-assets 搜索得到的准确虚拟路径。
# AssemblyPath 与 ProfilePath 使用已确认存在的本地安装和私有配置。
& scripts/inspect-nzm-bytecode.ps1 -Assets $assets -AssemblyPath $assemblyPath -ProfilePath $profilePath

# jsonPath 是上一步返回的导出 JSON 文件路径。
python scripts/summarize-nzm-bytecode.py $jsonPath --function ExecuteUbergraph
```

使用前查看脚本参数与本地前提。导出脚本通过反射访问已有 FModel CLI 程序集，开启 `ReadScriptData`，需要与该程序集兼容的 PowerShell/.NET 环境。它重新挂载私有配置指向的游戏，输出到被忽略的 `kismet/<环境>/<快照>/`；环境通过 `-Dataset` 声明，未确认时默认 `unknown`。不能拿本地 `.uasset` 路径代替虚拟路径，不能保证与旧导出同版本。

这是现有兼容入口，不是稳定的 FModel 公共字节码 API。失败时检查程序集、运行环境与实际诊断；不复制一份新反射脚本、不自动构建或下载工具。不要输出私有配置或凭据。`nzm-assets` 当前没有 `--bytecode` 选项。

摘要脚本的 `--function` 是子串匹配，需核对实际函数名；`--match` 只用于定位。摘要会压缩 `Owner`、`ObjectPath` 等信息，不能据此区分同名对象或推导完整执行路径。所有结论回到完整 JSON 核验。

## 读一个函数

1. **确定入口。** 记录完整函数身份。事件包装函数调用 `ExecuteUbergraph` 时，检查传入的入口参数与跳转位置；一个 Ubergraph 可包含多个事件，不能把全部语句视为一次连续执行。
2. **定位目标调用。** 搜索函数名、字段或 ID，保留所在完整表达式及调用上下文。调用可能嵌套在赋值或 `EX_Context` 等表达式中，不能只扫描顶层 Token。
3. **检查入口到调用的路径。** 阅读相关分支、跳转、循环和提前返回。只有能到达该调用的路径才参与结论；不能从 JSON 数组顺序直接推导执行顺序。
4. **追参数。** 检查接收者、参数、返回值及其所属对象。按需要反向追局部赋值、函数输入、CDO 或被调用函数；多条可达路径赋不同值时分别列出。
5. **核验执行后的行为。** 仅在问题涉及次数、周期、持续时间等时，继续检查重入、计时、回调、取消与清理路径。证据足够回答当前问题就结束。

不要求生成整包控制流图或完整伪代码。短函数可以直接说明路径；复杂函数可列“原始位置 → 条件 → 下一位置”。无法解释的跳转或 opcode 保留为未知，只限制依赖它的结论。

## 指令判读要点

| 读到什么 | 应检查什么 |
| --- | --- |
| `EX_Jump`、`EX_JumpIfNot` | 跳转目标及条件，分别追跳转边和适用的顺序执行边 |
| `EX_PushExecutionFlow`、`EX_PopExecutionFlow` 及条件变体 | 执行流栈保存与恢复的目标，不能把 Pop 简化成函数返回 |
| `EX_ComputedJump`、switch 类表达式 | 目标或分支选择的输入；不能确定时列出边界 |
| `EX_Let` 及赋值变体 | 左侧变量身份、右侧表达式，以及到目标调用前是否又被赋值 |
| `EX_Context`、对象/属性访问 | 接收者来源及上下文有效性，保留 Owner 与完整路径 |
| Final / Virtual / Local 等调用表达式 | 完整函数身份、签名与参数；动态派发无法确定具体实现时明确说明 |
| Return、结束标记 | 区分函数返回与脚本序列终止标记，不让不可达代码参与统计 |

具体字段形状和偏移语义以当前解析器输出及实现为准。保留原始 `StatementIndex`、`CodeOffset` 等字段名；先确认哪个表示源位置、哪个表示目标，再连边。不要把语句数组下标、脚本偏移和文件字节位置混为一谈，也不要按 JSON 文本长度计算偏移。

## 调用、参数和异步

- 参数有可靠签名时使用参数名；签名缺失时按“参数 0/1/…”引用，语义标为待确认。保留类型及对象来源，尤其区分输出参数和返回值。
- 常量传参证明该路径传入这个值。要证明最终效果，还需核对被调用实现、单位、覆盖及接收对象；Native 调用只能直接证明可见的调用条件和参数。
- Delay、Timer、Delegate、异步任务通常体现为调用及相关数据。检查绑定函数、回调对象、恢复入口、重复设置和取消行为；一次绑定不代表回调发生一次。
- 两个调用点可能互斥；循环体中的一个调用点也可能执行多次。报告每次事件触发的次数时，说明路径、循环边界与异步前提。
- 用 `Delay(0.5)` 不能单独证明攻击周期为 0.5 秒；总周期还可能包含前后执行、动画、冷却或运行时调度。

## 证据写法

最小记录为：结论与条件 + 输入文件/来源 + 函数身份 + 原始节点位置 + 关键参数及其来源。伪代码注明为人工整理，并保留回到原始节点的定位；未知调用或分支不要改写成确定语义。

例如，证据只覆盖某事件的一条分支时，写“该入口在条件 X 成立时，对对象 Y 调用 Z，参数 1 为 2”；不要扩大成“此效果始终为 2”。

引用偏移时绑定当前文件快照，长期复核可附 SHA-256；旧版本偏移断言用于发现证据漂移，不是新版本机制判定。无法找到调用也不能仅凭搜索结果宣称行为不存在，还可能来自父类、动态派发或不可见实现。
