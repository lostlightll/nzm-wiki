# NZM UAsset 分析

根据问题选择下面的分析方式，可以组合使用；证据足够回答问题时结束，不要求依次完成五类分析。

## 接收资产

- 接收本地 `.uasset`、完整导出 JSON 或准确虚拟路径。先确认输入对应的资产和来源版本；来源不明就标为未知，目录名不能证明游戏版本或服务器环境。
- 原始包与 JSON 是两种输入。已有 JSON 可以直接分析；只有原始包时，先确认现有解析工具支持该包、版本和所需 mappings。保留同批导出的配套文件，按包需求检查 `.uexp`、`.ubulk` 等，不假定只有 `.uasset` 就够，也不假定每个包都有配套文件。
- 缺属性 JSON 或关联资产时，读取 [nzm-assets](../nzm-assets/SKILL.md)，使用其 `inspect` / `extract`。`inspect` 接收虚拟路径并重新读取配置的游戏，不接收本地 `.uasset`；新导出不能自动视作旧包的解析结果。
- 当前没有在此 skill 中验证过的本地原始包解析命令。若只有本地包且没有可用解析器，报告缺少的能力；不要虚构命令或用其他版本 JSON 冒充它的内容。字节码的现有获取方式见下方专项参考。
- 分析前读取项目 `docs/README.md`，按问题路由相关规范。`refs/`、`refs-test/` 及 `kismet/` 已有证据只读；字节码导出按[参考库规范](../../../docs/workflows/kismet-evidence.md)新增快照。人工分析记录放 `MD/_local/nzm-uasset/<主题>/`，无需为简单问题建立完整报告目录。

## 1. 属性解析

适用：默认伤害参数、持续时间、组件配置、数据表行、曲线等“配置是什么”的问题。

1. 在导出 JSON 中用 `rg` 定位目标字段或标识，再读取它所在的完整对象。记录对象名、类型、字段路径，区分实例属性、类默认对象（CDO）和表行。
2. 字段缺失或存在覆盖疑问时，追父类默认对象、组件模板或具体实例。明确值来自哪一层；缺字段不等于零，父类值也不能直接覆盖子类显式值。
3. 数组保留成员身份与顺序；曲线保留时间、插值及关联参数，不能仅摘一个数值当作恒定值。
4. 得到目标配置及其来源即可回答。只有问题涉及“实际何时使用、是否被覆盖”时，再进入引用或字节码分析。

本站武器、插件的数值按现行 Numerical 规范沿身份链确认；描述用于语义辅助。属性默认值与实际运行结果分别表述。

## 2. 引用追踪

适用：某个技能、MGE、弹体、组件或配置关联谁，以及哪个入口使用它。

1. 从已知对象的具体引用字段出发，保留 `ObjectPath`、`ObjectName`、软引用路径及所属对象；按导出格式解析，避免仅按文件名拼路径。
2. 读取目标对象，核对身份，再沿与问题相关的字段继续。Import / Export 引用只能证明关联，实际启用还需装配、选择条件或执行证据。
3. 记录一条可复查的链：源对象与字段 → 目标对象 → 下一字段。遇到缺失资产列出准确路径；遇到循环记录后结束该分支。

追到目标配置或使用点即结束；不要为一个问题默认递归整个目录。资产目录中的同名、皮肤或其他模式变体要按引用身份区分。

## 3. Kismet 字节码分析

适用：触发条件、调用顺序、调用次数、参数来源、动态覆盖、延迟和回调。

读取 [Kismet 使用规范](references/kismet.md)，按实际问题定位函数并检查相关控制流和数据流。属性或函数签名不足以回答执行问题时，明确需要字节码；不从命名或描述补写执行逻辑。

## 4. 类型专用解析

适用：动画通知与 Montage 段、行为树节点、材质表达式、声音等专有结构。

- 先确认类型，查看现有 JSON 是否已提供目标结构，再选择已安装且支持该类型的工具；不默认需要新工具或原始二进制分析。
- 动画问题读取段范围、通知时间与关联调用；推导实际时序还需播放速率、循环、中断等证据。行为树检查连接、装饰器和服务。材质连接说明渲染计算，不直接证明玩法数值。
- 专用数据未导出或解析器不支持时，指出缺少的结构。引用了动画或某节点，不代表它必然执行。

## 5. 二进制结构检查

适用：包打不开、导出不完整、版本不匹配或怀疑解析器漏读。

- 从实际错误、文件大小、包头、配套文件和解析器版本入手。需要比较输入身份时计算文件哈希。
- 版本、mappings、偏移等判断须有包信息或工具诊断依据；字符串搜索只能提供线索，不能把命中的字节直接当成有类型的属性或执行指令。
- 确认失败原因或当前缺失条件后结束。输入或工具条件不变时，不重复尝试相同解析，也不修改原始包“修复”证据。

## 交付结论

按问题给出结论、成立条件和证据位置即可，不倾倒整个 JSON。证据位置包含虚拟资产路径、实际读取文件的绝对路径、对象/函数及字段或原始节点定位。

将直接读到的配置、沿代码推导的行为、尚未确认的运行结果区分开。跨版本比较时先对齐来源和对象身份，再比较属性或指令；偏移变化本身不代表机制变化。运行时观察与 Native 实现分析属于额外取证，不自动纳入本 skill 的任务。
